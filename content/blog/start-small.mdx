学习编程的路上，我们很容易收藏太多教程，却迟迟没有开始自己的项目。一个小而完整的作品，往往比一份漫长的学习清单更能带来进步。

## 先找到一个小问题

从每天遇到的不便出发：整理书签、记录读书笔记，或为自己的开源项目写一份清晰的文档。把目标写成一句话，让第一版只解决这一个问题。

> 一个有用的起点：让今天的自己比昨天少重复做一件事。

## 做出可以使用的第一版

从数据、交互和反馈三个部分拆解需求。先让核心流程跑通，再改善体验。

```typescript
interface Idea {
  problem: string;
  firstStep: string;
}

const idea: Idea = {
  problem: "学习笔记散落在不同地方",
  firstStep: "做一个可以搜索的笔记列表",
};
```

## 把过程也记录下来

为什么选这个技术？遇到了什么问题？下次会怎么做？这些真实的问题，就是技术博客最好的素材。

每一次提交，都是一次可见的进步。你可以从 [门户项目](/semicoder) 看起，或者阅读 [开发文档](/semicoder/docs/getting-started)。
