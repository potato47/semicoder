## 先从内置示例开始

在「应用中心」点击随手记卡片上的「安装示例插件」，安装后即可使用。随手记通过宿主 KV 存储，不依赖模型，是验证插件安装流程的最短路径。

## 支持的来源

| 来源   | 输入形式                   | 要求                                                |
| ------ | -------------------------- | --------------------------------------------------- |
| 本地包 | 选择 `.tgz` 或输入绝对路径 | 由 `bun pm pack` 打包，包含 manifest 和构建产物     |
| npm    | 包名或带版本包名           | 包真实存在且预先构建；当前不提供公开插件市场        |
| Git    | `git+https://…` 来源       | 仓库中包含可直接使用的 `dist`，安装时不会替插件编译 |

在安装框中输入来源，或点击「选择本地包」，再点击安装。安装任务完成后检查卡片状态，前端渲染失败与后端激活失败会分别提示。

本地归档流程已经实测。npm 和 Git 来源的实现已存在，但尚未用真实远端插件逐一验收；不要把示例包名称当成已发布 npm 包。

## 信任与执行

首版插件是可信本地扩展，能执行本机代码，与宿主共享进程能力。只安装你信任的包。禁用安装脚本不等于隔离插件：插件自己的前端与后端仍会在使用时执行。

## 启用、停用与卸载

应用中心可打开、停用、重新启用或卸载第三方插件。存在相关模型任务或方法调用时，宿主会阻止停用或卸载，先等待结束或取消任务。

卸载保留插件 KV 与运行历史。当前升级方式为手动卸载后安装新版，没有自动升级与回滚；保持相同插件 ID 才能延续数据。内置译文不能作为第三方插件卸载。

## 从 CLI 安装

在正在运行的开发项目目录执行：

```bash
bun run agent call plugins.install --json '{"source":"/absolute/path/plugin.tgz"}'
bun run agent call plugins.jobs --json '{}'
bun run agent call plugins.list --json '{}'
```

`plugins.install` 返回安装任务，接受任务不表示安装成功。继续通过 `plugins.jobs` 查看终态。安装正式应用的 CLI 后，命令前缀可替换为 `malatang`。

准备自己的包见 [插件开发](/malatang/docs/plugin-development)。
